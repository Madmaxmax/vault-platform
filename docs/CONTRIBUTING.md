# Правила работы команды

- Отдельная ветка `feature/<issue>-<topic>` от `main`, pull request с описанием изменений и тестов.
- Никаких секретов, `.env`, root token, SecretID, DB паролей в Git или PR.
- Изменения `infra/vault/` проходят ревью DevSecOps; `docker-compose.yml` и CI — DevOps + ревью DevSecOps для критичных частей.
- В PR прикладывайте подтверждения: номер задачи, реальные даты, скриншот результата/логи без секретов.
- Недельный план приведён в `ROADMAP.md`; выполненные задачи подтверждаются кодом, тестами и pull request.
