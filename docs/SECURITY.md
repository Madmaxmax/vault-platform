# Модель безопасности и ограничения

## Границы учебного стенда

- Приложение не получает root token, PostgreSQL admin password и AppRole SecretID.
- Bootstrap получает временные полномочия администратора Vault; используется только для начальной инициализации.
- Vault Agent получает RoleID / SecretID из локальных файлов и рендерит временную пару в tmpfs.
- `app` подключается к PostgreSQL напрямую и не контактирует с Vault API.
- ACL делит пути по продуктам и назначению; тест демонстрирует отказ чтения соседнего продукта.

## Перед реальной эксплуатацией

1. Удалить `-dev`, включить TLS с проверкой SAN и CA.
2. Перевести Vault в отдельную приватную ВМ, настроить Yandex KMS Auto Unseal и доступ только из доверенных сетей.
3. Реализовать безопасную доставку одноразового SecretID (response wrapping), права файлов и обновление credential material.
4. Настроить резервные копии Raft, протестировать восстановление, выбрать HA и процедуру реакции на компрометацию.
5. Вынести DBA-учётку из Compose env и перейти на управляемый безопасный bootstrap.
6. Включить аудит с защищённым хранением, минимизировать доступ к логам и системным файлам.
7. Интеграционно проверить срок жизни lease, отзыв, активные соединения и поведение приложения при ротации.
8. Добавить сканирование зависимостей, секретов, образов и политики доставки CI/CD.
