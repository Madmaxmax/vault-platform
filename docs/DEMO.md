# Сценарий демонстрации (после проверки на Docker-хосте)

1. Запустить `docker compose up --build -d`. Убедиться, что `bootstrap` завершился с кодом 0.
2. `curl http://localhost:8080/health` — API доступен.
3. `curl http://localhost:8080/db/check` — соединение под динамической ролью, выданной Vault. Не показывать пароли.
4. `./scripts/access-check.sh` — разрешённое чтение и отказ к секрету другого продукта.
5. `docker compose logs vault | tail -20` — аудит Vault-запросов; проверить отсутствие секретов в выводе перед демонстрацией.
6. Пример отзыва lease: **вручную** получить новый lease из `vault read -format=json database/creds/app-readonly`, сохранить lease ID в переменную и вызвать `vault lease revoke <id>`. Не вставлять логины и пароли в слайды.
7. Объяснить, что инстанс `-dev` не предоставляет TLS/HA и не подходит для production.

## Не подтверждено без инфраструктурного прогона

Полная работа Vault Agent, реакция приложения на ротацию PostgreSQL-креденшелов, аудит, revoke при активных соединениях, совместимость tmpfs Compose с конкретным Docker Desktop. Сценарий следует провести и приложить фактические логи до сдачи.
